# ui-merge

Three-way-merged UI groups stored as data so the build is reproducible (gadconv spec, policy 8), owned by the UI merge
area (package `com.gadscape.cacheconv.uimerge`). Generated by `UiMergeMain gen`; do not edit by hand (change
`UiMergeSpecs` / `ScriptRecipes` and regenerate; `UiMergeMain check` fails when the data is stale).

| file | what |
|---|---|
| `manifest.tsv` | one row per user-modified vanilla interface (12, 121, 160, 161, 164, 192, 205, 215, 218, 465, 476, 548, 621, 629) and clientscript (37 205 336 342 393 414 423 426 687 699 701 702 912 1074 1090 1092 1261 1311 1448 1705 2066 2094 2096 2186 2200 2735 3178 3310 4073 4104 6138): decision (merged / user / base), data file, SHA-256 of the BASE group it was made against, note |
| `interfaces/ID.if` | merged components: id, origin (merged / added / user), 241 bytes in hex, USER-sourced references that follow the id map |
| `scripts/ID.cs2` | merged script in text assembly (`u` = GadScape's line, `@kind` = its operand is an id of that kind) |
| `component-remap.tsv` | 211 -> 241 component ids for every vanilla interface the server references (same columns as `ui/interface-remap-211-241.tsv`, which it supersedes for ui-convert); keyed by GadScape's 211 numbering |
| `NOTES.md` | per id: what the user changed, how it was re-applied, what was not and why; open issues |
